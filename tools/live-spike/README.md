# T7 실시간 동풍전 엔진 실험

Epsilon 소스 `7630d15`에서 빌드한 리뷰어 jar와 Prism v760 체크포인트를 사용한다. 콘솔의 사람 좌석 두 곳은 브라우저 입력을 흉내 낸 스크립트가 맡고, 두 AI 좌석은 실제 모델이 맡는다. 웹 서버에서 방을 열거나 게임 데이터를 쓰는 기능은 T8 이후 범위다. [v760 릴리스](https://github.com/KoutaChan/Epsilon/releases/tag/epsilon-prism-v760)

## 재현

`scripts/setup-jdk.ps1`, `scripts/fetch-vendor.ps1`, `scripts/build-epsilon-cuda.ps1`로 기존 의존성을 준비한 환경에서 실행한다.

```powershell
.\tools\live-spike\run.ps1 -Device gpu0
```

클래스는 Java 21 대상으로 컴파일해 `data/live-spike/classes`에 저장한다. 아래 측정에는 JDK 23.0.2를 사용했고 결과는 콘솔에 출력했다. CPU 진단은 같은 명령에 `-Device cpu`를 넘긴다. CUDA 빌드 jar에는 CPU JNI 리소스가 없어 릴리스 jar의 CPU DLL만 추가했다. 이 조합은 모델을 열었지만 첫 추론에서 NaN을 반환했다. 현재 실험을 재현할 수 있는 경로는 CUDA다.

## 엔진 연결

| 단계 | 확인한 인터페이스 | 앱에서 관리할 값 |
| --- | --- | --- |
| 국 시작 | `Engine.startRecordedRound(RoundStart, int[] wall)`에 물리 패 136장의 전체 순서를 넘긴 뒤 `advance` | 경기 쌍과 국·본장별 패산, 같은 초기 좌석과 점수, 현재 경기 |
| 행동 대기 | `Engine.decisions()`가 응답할 좌석, 판단 ID, 합법 행동을 반환 | 국과 연결된 선택 토큰, 응답한 좌석과 유효한 제출 |
| 행동 확정 | 각 좌석 응답을 슬롯 순으로 모아 `Engine.commit`으로 반영 | 같은 판단 시점의 좌석 응답을 모두 모은 뒤 한 번 확정 |
| 좌석 화면 | `Engine.view(seat)`가 좌석 손패와 공개 이벤트를 제공 | 좌석 인증과 필요한 공개 필드만 담은 응답. 상대의 비공개 패·패산·시드는 서버에 보관 |
| AI 행동·추천 | `ObservationWriter.capture`로 해당 좌석 입력을 만들고 `PrismPolicy.evaluate`로 합법 행동 순서의 가치와 AI 선택을 받음 | AI 좌석은 전체 합법 행동을 선택. 학습자 추천은 두 번째 경기의 일반 타패(`DAHAI`)만 골라 그중 최선과의 가치 차이를 반환 |
| 정산 | `RoundEnd.next()`가 점수·공탁·다음 국·본장을 제공 | 동풍전 종료 판정. 기록용 국 시작 API는 국말 이후 자동 배패를 지원하지 않아 다음 국도 앱이 시작 |

엔진은 하나의 스레드에서 사용하도록 설계됐다. 방별로 상태 전이를 직렬화하고, 다음 `advance` 또는 `commit` 전에 응답에 필요한 값을 복사한다. 여러 좌석에 응답이 열린 경우 합법 행동 목록은 각각의 좌석에만 보낸다. [Epsilon Engine 소스](https://github.com/KoutaChan/Epsilon/blob/7630d15bc70a1fb9557408e2e7cd12e0b20a8d7b/epsilon-mahjong/src/main/java/com/epsilon/mahjong/engine/Engine.java)

## 동풍전 규칙 검토

아래 실험 규칙은 제안이다. Epsilon의 국 정산과 진행을 활용하고, 앱이 동풍전 종료를 판정한다. 천봉의 4인 동풍전에는 점수 조건에 따른 남입과 오라스 친의 화료·텐파이 종료가 있다. [천봉 4인 단위전 규칙](https://tenhou.net/man/)

| 항목 | 실험에서 적용한 기준 | 후속 결정 |
| --- | --- | --- |
| 시작 점수·자리 | 각 25,000점. 두 경기에서 같은 기점 친과 좌석 | 25,000점 유지 여부. 변경 시 엔진의 총점 불변조건도 검토 |
| 연장·본장 | 엔진의 친 화료·텐파이 연장, 도중유국, 본장·공탁 처리 | 동4국 오라스의 화료·텐파이 조기 종료 여부 |
| 동풍전 종료 | 동4국에서 친이 넘어가면 종료. 친이 이어지면 동4국 연장 | 목표 점수·남입 조건과 최대 국을 정하고 정책에 반영 |
| 토비 | 엔진 기준인 0점 미만에서 종료 | 0점 포함 여부 |
| 화료 정산 | 엔진의 론·쯔모, 복수 화료·공탁·본장 처리 사용 | 복수 론 정책과 예외 사례 확인 |
| 종료 점수·순위 | 남은 공탁은 1위에게 한 번 지급. 동점은 기점 친에 가까운 좌석 우선 | 순위 표시와 우마·오카 적용 여부 |

배패와 패산은 국·본장 키로 재생한다. 실험의 고정 seed는 재현용이다. 실제 방에서는 예측하기 어려운 난수로 생성한 패산을 서버에 저장하고, 브라우저에는 필요한 패만 보낸다. Epsilon의 `startGame(seed, ...)`은 진행 순번에 따라 패산을 바꾸므로 중간 연장 여부가 두 경기에서 갈릴 경우 사용하지 않는다.

## 검증 결과

Windows, RTX 4070 Ti, CUDA BF16 NATIVE, 단일 방에 해당하는 순차 1행 추론 기준이다.

| 항목 | 표본 | p50 | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: |
| AI 좌석 판단 | 318 | 15.05ms | 15.71ms | 28.45ms |
| 사람 좌석 타패 추천 | 128 | 15.18ms | 15.99ms | 16.26ms |

- 모델 로딩 2.22초. AI 좌석에 합법 행동이 하나뿐인 경우는 추론 표본에서 제외했다. 타패 추천 시간에는 후보별 가치를 손실로 변환하는 시간이 포함된다.
- 동풍전 두 경기 모두 완료. 공통 국·본장 4개에서 패산 136장, 네 좌석의 초기 손패, 첫 쯔모, 도라 표시패를 대조했다. 첫 타패와 최종 점수는 두 경기에서 달랐다.
- 사람 입력 316건, AI 좌석 응답 330건, 여러 좌석에 동시에 열린 응답 창 6개를 처리했다. 첫 추천의 합법 타패 11개에서 유한한 가치와 손실을 받았다.
- 상대의 미공개 손패 한 장과 미래 패산 한 장을 바꾼 상황에서 현재 좌석의 모델 입력이 바이트 단위로 일치했다. 상대 쯔모 마스킹, 불법 행동 거부 후 국면 유지도 확인했다.
- 동4국 친 텐파이 후 연장, 친 노텐 후 종료, 종료 공탁 수령을 별도 정산 상태에서 검증했다.
- 기존 Python 회귀 테스트 55개 통과.

브라우저 왕복과 여러 방 동시 추론은 측정 범위 밖이다. 두 경기의 실제 국·본장 경로는 같았다. 한 경기에서만 연장한 뒤 공통 국·본장에 복귀하는 통합 검증은 T8에서 수행한다. Prism v760은 동남전으로 학습됐으므로 이 가치가 앱의 동풍전 종료 조건을 직접 평가하는지 별도 검증이 필요하다.
