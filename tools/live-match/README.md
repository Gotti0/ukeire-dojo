# T8 동풍전 진행과 패산 재사용

`EastSeries`는 한 방에서 두 경기와 공통 패산을 관리한다. 최초로 등장한 국·본장을 배패할 때 `SecureRandom`으로 물리 패 136장을 섞어 보관한다. 이후 같은 키를 만나면 그 배열을 Epsilon에 다시 전달한다. 다음에 처음 등장하는 국·본장만 새로 섞으므로 경기마다 연장 횟수와 등장 순서가 달라도 대응하는 패산은 같다.

## 진행

1. 새 `EastSeries`의 `first()`는 동1국 0본장, 네 좌석 25,000점에서 시작한다.
2. `decision(seat)`에서 해당 좌석의 합법 행동 코드와 현재 결정 번호를 읽는다. 방은 같은 결정의 좌석별 응답을 모아 `commit(revision, actionsBySeat)`로 한 번에 전달한다. 지난 시점의 입력이나 합법 목록에 없는 행동은 거부된다.
3. 국말에는 `settlement()`에서 결과, 점수 변화, 공탁, 순위, 다음 국·본장을 읽는다. `nextRound(settledRound)` 호출 시 다음 국을 배패한다.
4. 첫 경기 종료 후 `startReplay()`가 기존 패산으로 새 경기를 시작한다. 같은 호출을 반복하면 이미 시작한 두 번째 경기를 돌려준다.

동4국에서 친이 넘어가면 종료한다. 친이 이어지면 동4국을 연장하며, 최종 친의 화료·텐파이 시 별도 조기 종료와 남입은 적용하지 않는다. 0점 미만은 Epsilon의 토비 판정을 사용하고 0점은 계속한다. 동점은 기점 친에 가까운 좌석이 앞서고, 경기 종료 시 남은 공탁은 1위에게 한 번 지급한다.

방에서 각 경기 인스턴스를 단일 작업 스레드에서 다룬다. 결정 번호는 경기 내부 값이므로 방 요청에서는 경기 식별자와 함께 사용한다. 좌석 관측은 다음 상태 전이까지 유효한 엔진 뷰에서 필요한 값만 복사한다. 패산은 방 프로세스의 메모리에 보관하며, 방과 브라우저 연결은 T9에서 이어 붙인다.

## 검증

[T7 실험](../live-spike/README.md)에 사용한 Epsilon 리뷰어 jar와 JDK가 준비된 Windows에서 실행한다. 이 검증은 게임 규칙 엔진만 사용하므로 실행 시 GPU나 모델 체크포인트가 필요 없다.

```powershell
.\tools\live-match\run-tests.ps1
```

- 실제 엔진을 서로 다른 두 스크립트 정책으로 끝까지 진행했다. 첫 경기는 동4국 3본장에 곧바로 도달했고, 두 번째 경기는 동4국 2본장에서 연장한 뒤 동4국 3본장에 도달했다. 공통 국의 네 좌석 배패와 도라 표시패가 같았고, 무작위 셔플을 다시 호출하지 않았다.
- 국 사이 점수와 공탁이 이어지고 총점과 공탁 합계 100,000점이 보존되는 것을 확인했다. 동4국 친 텐파이 연장, 친 노텐 종료, 남은 공탁 수령, 동점 순위, 0점 유지와 음수 종료도 검증했다.
- 불법 행동, 지난 결정 번호와 국말 진행 재전송을 거부했고, 두 번째 경기 시작 재요청 시 기존 경기를 반환했다.
