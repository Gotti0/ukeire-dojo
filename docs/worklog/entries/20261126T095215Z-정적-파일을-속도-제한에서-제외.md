## 배경

공개 호스팅 보강 때 IP별 토큰 버킷(초당 5회, 순간 30회)을 모든 요청에 걸었다.

## 문제

외부(휴대폰 데이터망, 106.101.x.x)에서 접속하자 패 이미지가 로딩되지 않았다. 접속 기록에서 429 32건이 모두 이 IP의 `/tiles/*` 요청이었다. 화면 한 번에 HTML, JS, CSS와 패 이미지 수십 장을 받아 순간 한도를 바로 넘었다. 집 안에서 DDNS로 들어오면 모든 기기가 공유기 IP 하나로 보이므로 한도에 더 빨리 걸린다.

## 결정과 근거

- 속도 제한은 API 요청(`/api/*`)과 인증 실패에만 건다. 인증을 통과한 정적 파일은 디스크에서 읽어 줄 뿐이라 막을 이유가 없다.
- 정적 파일을 통째로 예외로 두는 안은 버렸다. 그러면 정적 경로로 암호를 무제한 대입할 수 있다. 인증 실패는 경로와 상관없이 계속 센다.
- 브라우저 캐시를 켰다. 모두 인증 뒤의 내용이라 `private`이다.
  - Vite의 해시 파일(`assets/`)은 1년, immutable.
  - 패 이미지는 1일.
  - `index.html`은 no-cache. 새 빌드의 해시 이름을 가리켜야 하기 때문이다.

## 검증

- 서버 테스트 15개가 통과했다.
  - 인증된 정적 요청 10회는 모두 200이다.
  - API는 한도를 넘으면 429다.
  - 틀린 암호는 401 3회 뒤 429다.
  - 캐시 정책 테스트도 추가했다.
- 서버를 다시 띄워 DDNS 주소로 화면 한 번 분량(41요청: index, JS, CSS, 패 이미지 38장)을 20개씩 병렬로 보냈다. 41개 모두 200이었다.
- 캐시 헤더가 파일 종류별로 의도대로 나가는 것을 확인했다.

## 미해결

- HEAD 요청은 처리하지 않는다(501). 브라우저 사용에는 영향이 없다.
- 고친 뒤 외부 휴대폰 화면에서 이미지가 다 뜨는지는 사용자가 확인해야 한다.
