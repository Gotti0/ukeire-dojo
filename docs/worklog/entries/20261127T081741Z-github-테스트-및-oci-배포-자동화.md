## 배경

2026-11-27 확인 시 GitHub 워크플로가 없었고 OCI의 Python 체크아웃과 프런트엔드 빌드는 수동으로 갱신되고 있었다.

## 문제

대국 통합 테스트는 Epsilon main Java API를 쓰고 패보 분석 테스트는 v760 릴리스 CPU 런타임을 쓴다. v760 릴리스 jar 단독으로 대국 호스트를 빌드하면 main의 패와 대국 엔진 API가 없어 컴파일이 실패했다. main 전체 소스를 v760 jar와 함께 컴파일해도 학습 코드의 DJL API 버전이 달랐다.

## 결정과 근거

CPU CI에는 검증한 릴리스 jar와 고정된 Epsilon main 소스를 사용해 스크립트 봇에 필요한 Java 클래스만 빌드한다. PR과 main에서 테스트를 실행하고, main의 테스트 성공 뒤에만 프런트엔드 빌드를 게시한다. OCI는 해당 빌드의 부모 커밋이 main에 포함됐는지 확인해 실제 운영 Java jar로 컴파일하고 소스와 정적 파일을 함께 전환한다. 서비스는 기존 절대 경로의 운영 DB와 모델을 사용한다.

## 검증

- 깨끗한 작업 사본에서 Python 61개, Java 5개 통과. Node 프롬프트 테스트 4개, Vite 빌드, actionlint와 Bash 구문 검사 통과.
- OCI 격리 경로에서 실제 Java 컴파일, 배포 전환, 중복 배포 생략, 헬스 체크 실패 시 복귀를 검증했다.
- 2026-11-27 배포 타이머 설치 후 기존 서비스 PID와 로컬 통계 API의 HTTP 200을 확인했다.

## 미해결

- 첫 공개 운영 배포는 워크플로가 main에 병합되고 테스트를 통과한 뒤 발생한다. 서비스 재시작 시 메모리의 대국 방은 종료된다.
