## 배경

브리프는 Riichi-Trainer(GPL-3.0)를 포크해 손패 렌더링과 효율 계산 JS를 재사용하는 계획이었다. T3까지 효율 계산은 Python으로 문제은행에 이미 들어갔다.

## 문제

Riichi-Trainer는 React 16과 react-scripts 3.4(webpack 4), jQuery, Bootstrap 4 기반이다. 이 환경의 Node 22에서는 legacy OpenSSL 옵션이 있어야 빌드될 가능성이 크고, 오래된 의존성 경고가 많다. 포크로 얻을 것은 패 렌더링과 이미지 정도로 줄어든 상태였다.

## 결정과 근거

- 포크를 버리고 Vite 6 + React 19로 화면을 새로 만들었다. 가져온 것은 패 이미지 38장(CC BY 4.0, 출처는 `web/public/tiles/ATTRIBUTION.md`)뿐이다.
- 서버는 표준 라이브러리(ThreadingHTTPServer)로 만들고 localhost에만 연다.
  - 문제 응답에서는 상대 손패와 정답(효율·AI 값)을 뺀다.
  - 채점은 패 종류 단위다(적5는 같은 종류). 손실은 타패와 리치 선언 중 작은 값이다.
- 무작위 출제는 `ORDER BY random()`로 한다. 18만 행에서도 수십 ms라 난수 인덱스 열을 두지 않았다.

## 검증

- 합성 문제은행으로 서버 테스트 6개를 돌렸다.
  - 문제 응답에 상대 손패와 정답이 새지 않는다.
  - AI 손실 순서로 채점하고, 적5를 처리한다.
  - 필터가 동작하고, HTTP로 왕복할 수 있다.
  - 정적 경로로 루트 밖 파일을 읽을 수 없다.
- 전체 pytest 36개가 통과했다(gpu 1개 제외).
- 실제 문제은행(184,293문제)으로 브라우저에서 확인했다.
  - 출제, 채점 표, Enter로 다음 문제, 필터를 확인했다.
  - 필터(상대 리치 있음, 울기)를 걸고 20문제를 뽑았는데 모두 조건을 만족했고 정답 정보가 새지 않았다. 콘솔 오류는 없었다.

## 미해결

- 오답 기록과 약점 출제(T5), Claude 해설(T6)은 없다. 지금은 점수 집계가 화면 메모리에만 있다.
- 리치 선언 여부는 따로 묻지 않는다. 버릴 패만 받고, 표에서 리치했을 때의 손실을 보여 준다.
- 화면 레이아웃은 데스크톱 폭에서만 확인했다.
