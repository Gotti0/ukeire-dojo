## 배경

T9에서 한 방의 첫 번째 동풍전을 2~4인 브라우저와 AI로 진행했다. T10에서는 같은 방에서 동일 국·본장 패산으로 두 번째 동풍전을 이어 시작하고, 두 번째 경기에서만 요청형 타패 추천과 두 경기 결과 비교를 제공해야 했다.

## 문제

타패 추천은 1경기에는 금지하고 2경기 자기 타패 차례(`DAHAI`)에만 허용해야 한다. 또한 브라우저에서 추천 계산 도중 타패를 먼저 제출하면 뒤늦게 도착한 이전 추천이 새 차례 화면에 표시될 위험이 있으며, 1경기 종료 뒤 미복귀 참가자 처리와 동일 IP 다중 참가자의 API 속도 제한 여분도 함께 다뤄야 했다.

## 결정과 근거

- Java 호스트의 `discard_hint`는 `matchIndex == 2`와 `DAHAI` 후보만 평가하고, 손패·쯔모기리 중복 표기를 최선 가치 1건으로 합쳐 손실을 계산한다. Python 서버는 1경기 추천 요청을 `403`으로 거부하고, 요청자 본인에게만 결과를 반환한다.
- 프런트엔드는 `revision` 전환 시 진행 중 추천 요청을 `AbortController`로 취소하고, 응답 수신 시점과 렌더링 시점에 모두 현재 `revision` 일치를 검증해 지연 응답을 차단했다.
- 2경기 시작 시 미복귀한 참가자는 좌석과 토큰을 유지한 채 AI 대타로 시작해 재접속 시 즉시 복귀하게 했으며, 동일 IP에서 여러 브라우저가 대국할 때 `429`에 걸리지 않도록 기본 토큰 버킷을 `rate=20.0, burst=100`으로 조정했다.

## 검증

- Java 통합 검증 5개(`EastMatchTest`, 1경기 추천 거부·2경기 배패 일치·추천 상태 불변)가 통과했다.
- Python 테스트 62개(기존 60개 확장 + 1경기 추천 `403`·2경기 동일 패산/추천/비교·미복귀 대타 재개·실제 `prism gpu0` 2경기 타패 추천)가 통과했다.
- Vite 프로덕션 빌드(`574ms`)와 실제 `prism gpu0` 서버 대상 2브라우저 Chromium E2E에서 1경기 거부(`403`), 2경기 동일 배패, 요청자 한정 추천 표시, 지연 추천 차단, 2경기 완주 후 결과 비교 표를 확인했다.

## 미해결

- 두 브라우저 실플레이 최종 통합 검증과 중복·지연 입력 종합 확인은 T11 범위다.
